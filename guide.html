TMDB CLI: розбір ООП-версії

CLI зі списками фільмів TMDB, переписаний із функцій на класи: ієрархія помилок, абстрактний клієнт із шаблонним методом, value object-и, модель фільму й ін'єкція залежностей. Нижче видно, що робить кожен клас, чому код розкладено саме так і як це перевіряють тести.

Node.js ≥ 18 0 залежностей ES2022 класи приватні поля # node:test 34 тести

1. Що змінилось і навіщо

Раніше програма була набором функцій і плоских об'єктів: parseType, parsePage, fetchMovies, formatMovies. Тепер у ній є класи: кожен має одну роль, власні дані й методи, які працюють саме з цими даними. Поведінка не змінилась: вивід усіх сценаріїв командного рядка збігається з виводом старої версії символ у символ (див. розділ «Що перевірено»).

Чи завжди класи кращі за функції?

Ні. Для програми на 300 рядків функції були цілком нормальні, і ця версія навмисно навчальна: вона показує, як виглядають інкапсуляція, успадкування, поліморфізм і ін'єкція залежностей на живому коді. Кожен розділ нижче пояснює, що саме тут «з ООП» і що воно дає на практиці.

3. Чотири стовпи ООП на цьому коді

ПринципДе в проєктіПростими словами
Інкапсуляція#token у TmdbClient, #fetchImpl в ApiClient, #value у PageNumber, #values в EnvFileдані об'єкта сховано в приватних полях (#): зовні їх не прочитати й не зіпсувати, лише через методи. Токен не потрапить у лог випадково.
НаслідуванняTmdbClient extends ApiClient; ApiError extends UserError extends Errorнащадок отримує все від предка й додає своє. Другий клієнт (інший API) успадкував би той самий алгоритм запиту.
ПоліморфізмdescribeHttpError(), buildHeaders(), serviceNameбазовий клас викликає ці методи, не знаючи, чий саме код виконається: в TmdbClient вони свої. Той самий виклик, різна поведінка.
АбстракціяApiClient не можна створити напряму (new.target)клас описує «що вміє будь-який клієнт API», а конкретику залишає нащадкам.

Окрім стовпів, у коді є ще кілька корисних прийомів: value object (ListType, PageNumber), статичні фабричні методи (Movie.fromApi, ListType.parse), шаблонний метод (ApiClient.getJson), ін'єкція залежностей (CliApp) і генератор (MoviePage.numbered). Усі вони розібрані нижче.

4. Шлях одного запиту

Команда: node src/cli.js --type top --page 2.

  1. cli.js збирає об'єкти: EnvFile.load('.env') → Config.load(...) → new CliApp({ config, createClient }). Нічого не виконується, лише створюється.
  2. CliApp.run(argv) викликає приватний #execute. parseArgs розбирає прапорці.
  3. ListType.parse('top') → константа ListType.TOP. PageNumber.parse('2') → PageNumber(2). Неправильне значення дає UsageError ще до мережі.
  4. createClient(token) створює TmdbClient. Якщо токена немає, client.list() одразу кидає ConfigError, і запиту не буде.
  5. TmdbClient.list() будує URL (buildUrl) і викликає getJson із базового класу: запит із таймаутом, заголовки з buildHeaders(), помилки в NetworkError / ApiError.
  6. Відповідь перетворюється на MoviePage.fromApi(data): усередині кожен запис стає Movie.
  7. MovieFormatter.format(moviePage, listType) повертає текст, CliApp друкує його й атрибуцію TMDB.
  8. run повертає 0 (або 1 при помилці), а cli.js записує це в process.exitCode.

5. Ієрархія помилок

src/errors.jsуспадкування
// Ієрархія помилок (успадкування). Усе, що користувач може виправити сам, — це UserError:
// Cli друкує його коротко («Error: ...»). Будь-що інше вважається багом і друкується зі стеком.
//
//   Error
//    └─ UserError
//        ├─ UsageError    — неправильні аргументи (--type, --page)
//        ├─ ConfigError   — немає токена
//        ├─ NetworkError  — немає звʼязку з сервісом
//        └─ ApiError      — сервіс відповів помилкою (status зберігається в полі)
export class UserError extends Error {
  constructor(message, options) {
    super(message, options);
    this.name = new.target.name; // імʼя класу-нащадка: UsageError, ApiError, ...
  }
}

export class UsageError extends UserError {}

export class ConfigError extends UserError {}

export class NetworkError extends UserError {}

export class ApiError extends UserError {
  constructor(message, status, options) {
    super(message, options);
    this.status = status;
  }
}
  • Чому це корисно. CliApp питає лише «це UserError?» (instanceof). Усі п'ять класів підходять, бо всі нащадки UserError. Водночас код, який хоче, може розрізнити NetworkError і ApiError, наприклад, щоб повторити запит лише при мережевій помилці.
  • new.target.name дає ім'я реального класу (ApiError, а не UserError), тож в логах видно, що саме сталось, без окремого поля name у кожному класі.
  • ApiError.status зберігає HTTP-статус, щоб його можна було перевірити в коді, а не розбирати з тексту повідомлення.
  • { cause: err } у NetworkError: оригінальну помилку (fetch failed) збережено всередині нової, а не втрачено.

6. Доменні класи: ListType, PageNumber, Movie, MoviePage

ListType: value object зі статичними константами

src/ListType.jsvalue object
import { UsageError } from './errors.js';

// Тип списку фільмів: значення --type, шлях у TMDB і заголовок для виводу.
// Це «value object»: екземпляри створюються лише тут, як статичні константи, і заморожені.
export class ListType {
  static PLAYING = new ListType('playing', 'now_playing', 'Now Playing');
  static POPULAR = new ListType('popular', 'popular', 'Popular');
  static TOP = new ListType('top', 'top_rated', 'Top Rated');
  static UPCOMING = new ListType('upcoming', 'upcoming', 'Upcoming');

  static all() {
    return [ListType.PLAYING, ListType.POPULAR, ListType.TOP, ListType.UPCOMING];
  }

  static keys() {
    return ListType.all().map((type) => type.key);
  }

  // Рядок користувача → ListType (без урахування регістру й пробілів). Невідомий → UsageError.
  static parse(value) {
    const key = String(value ?? '').trim().toLowerCase();
    const found = ListType.all().find((type) => type.key === key);
    if (!found) {
      throw new UsageError(`Unknown type "${value ?? ''}". Use one of: ${ListType.keys().join(', ')}.`);
    }
    return found;
  }

  constructor(key, path, title) {
    this.key = key; // значення --type
    this.path = path; // частина URL у TMDB
    this.title = title; // заголовок списку у виводі
    Object.freeze(this);
  }
}
  • Статичні поля ListType.TOP тощо — єдині екземпляри. Усюди, де раніше був рядок 'top', тепер обʼєкт, у якого є й шлях TMDB, і заголовок. Не треба тримати окремий словник TYPES.
  • Object.freeze(this): після створення поля не змінити (є тест). Значення ніколи не «попливе» під час роботи.
  • static parse — «фабричний метод»: перетворює рядок користувача на об'єкт або кидає UsageError. Так parse('toString') не проходить, бо пошук іде серед чотирьох типів, а не через obj['toString'].

PageNumber: об'єкт, який неможливо створити неправильним

src/PageNumber.jsvalue object + приватне поле
import { UsageError } from './errors.js';

// Номер сторінки, який уже пройшов перевірку. Не можна створити PageNumber(0) чи PageNumber(501):
// якщо в руках є PageNumber, його значення правильне, і далі перевіряти не треба.
export class PageNumber {
  static MAX = 500; // TMDB не віддає сторінки далі за 500

  static parse(value = '1') {
    const number = Number(value);
    if (!/^\d+$/.test(String(value)) || number < 1 || number > PageNumber.MAX) {
      throw new UsageError(`Page must be an integer from 1 to ${PageNumber.MAX}.`);
    }
    return new PageNumber(number);
  }

  #value;

  constructor(value) {
    if (!Number.isInteger(value) || value < 1 || value > PageNumber.MAX) {
      throw new RangeError(`Invalid page number: ${value}`);
    }
    this.#value = value;
    Object.freeze(this);
  }

  get value() {
    return this.#value;
  }

  toString() {
    return String(this.#value);
  }
}

Було: parsePage повертав число, і кожне місце, що його отримало, мусило довіряти, що воно перевірене. Тепер перевірка в конструкторі: якщо у функцію прийшов PageNumber, значення гарантовано від 1 до 500. Конструктор викидає RangeError (це помилка програміста, а не користувача), а parse — UsageError (це помилка введення).

Movie і MoviePage: свої поля замість чужого JSON

src/Movie.jsмодель
// Один фільм. Приймає відповідь TMDB (snake_case) один раз у fromApi, а далі решта коду
// працює зі своїми полями й обчислюваними властивостями. Форматування для терміналу тут немає:
// воно в MovieFormatter, щоб модель не знала, як її показують.
export class Movie {
  static OVERVIEW_MAX = 110;

  static fromApi(raw) {
    return new Movie({
      title: raw.title,
      releaseDate: raw.release_date,
      voteAverage: raw.vote_average,
      voteCount: raw.vote_count,
      overview: raw.overview,
    });
  }

  constructor({ title, releaseDate, voteAverage, voteCount, overview }) {
    this.title = title;
    this.releaseDate = releaseDate;
    this.voteAverage = voteAverage;
    this.voteCount = voteCount;
    this.overview = overview;
  }

  get year() {
    return this.releaseDate ? this.releaseDate.slice(0, 4) : 'n/a';
  }

  get hasRatings() {
    return Boolean(this.voteCount);
  }

  // Опис в один рядок, обрізаний до OVERVIEW_MAX символів
  get shortOverview() {
    const flat = (this.overview ?? '').replace(/\s+/g, ' ').trim();
    const max = Movie.OVERVIEW_MAX;
    return flat.length > max ? `${flat.slice(0, max - 3).trimEnd()}...` : flat;
  }
}
src/MoviePage.jsколекція + генератор
import { Movie } from './Movie.js';

// Одна сторінка відповіді TMDB: номер, скільки всього сторінок і фільми (колекція обʼєктів Movie).
export class MoviePage {
  static SIZE = 20; // стільки фільмів TMDB віддає на сторінку

  static fromApi(data) {
    return new MoviePage({
      page: data.page,
      totalPages: data.total_pages,
      movies: (data.results ?? []).map((raw) => Movie.fromApi(raw)),
    });
  }

  constructor({ page, totalPages, movies }) {
    this.page = page;
    this.totalPages = totalPages;
    this.movies = movies;
  }

  get isEmpty() {
    return this.movies.length === 0;
  }

  // Нумерація наскрізна між сторінками: на сторінці 2 перший фільм має номер 21
  get offset() {
    return (this.page - 1) * MoviePage.SIZE;
  }

  // Ітерація «номер + фільм». Генератор: значення віддаються по одному.
  *numbered() {
    for (const [i, movie] of this.movies.entries()) {
      yield { number: this.offset + i + 1, movie };
    }
  }
}
  • Movie.fromApi — єдине місце, де зустрічаються release_date і vote_average. Якщо TMDB змінить формат, правка буде лише тут.
  • Обчислювані властивості (get): year, hasRatings, shortOverview виглядають як поля, а рахуються при зверненні. Логіка «що таке рік фільму» живе разом з даними.
  • *numbered() — генератор: віддає пари «номер + фільм» по одній. Наскрізна нумерація (offset + i + 1) тепер у MoviePage, бо вона залежить від номера сторінки, який ця модель і знає.
  • Чому Movie не вміє форматувати себе. Тоді модель знала б, як її показують у терміналі, і зміна виводу чіпала б модель. Це окрема відповідальність, наступний розділ.

7. ApiClient і TmdbClient: наслідування й поліморфізм

src/ApiClient.jsабстрактний предок
import { ApiError, NetworkError } from './errors.js';

// Абстрактний клієнт HTTP API. Тут лежить ЗАГАЛЬНИЙ алгоритм запиту (патерн «шаблонний метод»):
//   1. зробити запит із таймаутом;   2. мережа впала → NetworkError;
//   3. статус не 2xx → ApiError;     4. тіло не JSON → ApiError.
// А те, що різниться між сервісами (імʼя, заголовки, тексти помилок), нащадок дає сам, перевизначивши
// serviceName, buildHeaders і describeHttpError.
export class ApiClient {
  static DEFAULT_TIMEOUT_MS = 10_000;

  #fetchImpl;
  #timeoutMs;

  // fetchImpl передається ззовні: у тестах підставляємо підроблений fetch, мережа не потрібна
  constructor({ fetchImpl = fetch, timeoutMs = ApiClient.DEFAULT_TIMEOUT_MS } = {}) {
    if (new.target === ApiClient) throw new TypeError('ApiClient is abstract: use a subclass');
    this.#fetchImpl = fetchImpl;
    this.#timeoutMs = timeoutMs;
  }

  // ── Що має дати нащадок ──
  get serviceName() {
    throw new Error(`${this.constructor.name} must define serviceName`);
  }

  buildHeaders() {
    return { accept: 'application/json' };
  }

  describeHttpError(status, apiMessage) {
    return `${this.serviceName} error ${status}${apiMessage ? `: ${apiMessage}` : ''}`;
  }

  // ── Загальний алгоритм (шаблонний метод) ──
  async getJson(url) {
    let response;
    try {
      response = await this.#fetchImpl(url, {
        headers: this.buildHeaders(),
        signal: AbortSignal.timeout(this.#timeoutMs),
      });
    } catch (err) {
      const reason = err.name === 'TimeoutError' ? 'request timed out' : (err.cause?.code ?? err.message);
      throw new NetworkError(`Cannot reach ${this.serviceName}: ${reason}. Check your internet connection.`, { cause: err });
    }

    if (!response.ok) {
      let apiMessage;
      try {
        apiMessage = (await response.json()).status_message;
      } catch {
        // тіло помилки може бути не JSON — тоді вистачить коду статусу
      }
      throw new ApiError(this.describeHttpError(response.status, apiMessage), response.status);
    }

    try {
      return await response.json();
    } catch {
      throw new ApiError(`${this.serviceName} returned an invalid response.`, response.status);
    }
  }
}
src/TmdbClient.jsнащадок
import { ApiClient } from './ApiClient.js';
import { ConfigError } from './errors.js';
import { MoviePage } from './MoviePage.js';
import { PageNumber } from './PageNumber.js';

// Клієнт TMDB API v3. Успадковує загальний алгоритм запиту від ApiClient
// і додає лише те, що відомо про TMDB: адреса, токен, тексти помилок.
export class TmdbClient extends ApiClient {
  static BASE_URL = 'https://api.themoviedb.org/3';

  #token;

  constructor({ token, ...options }) {
    super(options); // fetchImpl, timeoutMs
    this.#token = token;
  }

  // ── Перевизначені методи базового класу (поліморфізм) ──
  get serviceName() {
    return 'TMDB';
  }

  buildHeaders() {
    return { ...super.buildHeaders(), Authorization: `Bearer ${this.#token}` };
  }

  describeHttpError(status, apiMessage) {
    if (status === 401) return 'TMDB rejected the token (401). Check TMDB_ACCESS_TOKEN.';
    if (status === 404) return 'TMDB returned 404: nothing found at this address.';
    if (status === 429) return 'Too many requests (429). Wait a moment and try again.';
    if (status >= 500) return `TMDB is having problems (${status}). Try again later.`;
    return super.describeHttpError(status, apiMessage); // решта — загальний текст із базового класу
  }

  // ── Своє ──
  buildUrl(listType, { page = PageNumber.parse(), language, region } = {}) {
    const url = new URL(`${TmdbClient.BASE_URL}/movie/${listType.path}`);
    url.searchParams.set('page', String(page));
    if (language) url.searchParams.set('language', language);
    if (region) url.searchParams.set('region', region);
    return url;
  }

  // Головний метод: список фільмів → MoviePage. Без токена в мережу не ходимо.
  async list(listType, options = {}) {
    if (!this.#token) {
      throw new ConfigError('TMDB access token is missing. Put TMDB_ACCESS_TOKEN in .env (see README).');
    }
    const data = await this.getJson(this.buildUrl(listType, options));
    return MoviePage.fromApi(data);
  }
}

Шаблонний метод

getJson у ApiClient задає порядок кроків: запит → помилка мережі → статус не 2xx → не JSON. А деталі кроків він бере в нащадка через методи, які той перевизначає:

МетодУ ApiClientУ TmdbClient
serviceNameкидає «має визначити нащадок»'TMDB'
buildHeaders(){ accept: 'application/json' }те саме плюс Authorization (через super.buildHeaders())
describeHttpError()загальний текст «error 400: …»свої тексти для 401, 404, 429, 5xx, а решту передає super

Це і є поліморфізм: getJson викликає this.describeHttpError(...), не знаючи, який клас перед ним. Завтра можна додати OmdbClient extends ApiClient з іншими текстами, не чіпаючи алгоритм.

super у двох ролях

super(options) у конструкторі викликає конструктор предка (передає йому fetchImpl і timeoutMs). super.buildHeaders() у методі викликає версію предка, щоб доповнити її, а не переписувати.

Абстрактність у JavaScript — домовленість

У мові немає ключового слова abstract. Тут воно імітується двома перевірками: new.target === ApiClient у конструкторі (напряму створити не можна) і геттер serviceName, що кидає помилку. Обидва випадки покрито тестами.

Було: одна функція fetchMovies (для порівняння)
src/tmdb.jsгілка main
// Робота з TMDB API v3. fetch передається параметром, тому в тестах мережа не потрібна.

export class UserError extends Error {}

export const BASE_URL = 'https://api.themoviedb.org/3';
export const MAX_PAGE = 500; // TMDB не віддає сторінки далі за 500
const TIMEOUT_MS = 10_000;

// Ключ — значення --type, path — частина URL у TMDB.
export const TYPES = {
  playing: { path: 'now_playing', title: 'Now Playing' },
  popular: { path: 'popular', title: 'Popular' },
  top: { path: 'top_rated', title: 'Top Rated' },
  upcoming: { path: 'upcoming', title: 'Upcoming' },
};

export function parseType(value) {
  const key = String(value ?? '').trim().toLowerCase();
  if (!Object.hasOwn(TYPES, key)) {
    throw new UserError(`Unknown type "${value ?? ''}". Use one of: ${Object.keys(TYPES).join(', ')}.`);
  }
  return key;
}

export function parsePage(value = '1') {
  const page = Number(value);
  if (!/^\d+$/.test(String(value)) || page < 1 || page > MAX_PAGE) {
    throw new UserError(`Page must be an integer from 1 to ${MAX_PAGE}.`);
  }
  return page;
}

export function buildUrl({ type, page = 1, language, region }) {
  const url = new URL(`${BASE_URL}/movie/${TYPES[type].path}`);
  url.searchParams.set('page', String(page));
  if (language) url.searchParams.set('language', language);
  if (region) url.searchParams.set('region', region);
  return url;
}

function httpErrorMessage(status, apiMessage) {
  if (status === 401) return 'TMDB rejected the token (401). Check TMDB_ACCESS_TOKEN.';
  if (status === 404) return 'TMDB returned 404: nothing found at this address.';
  if (status === 429) return 'Too many requests (429). Wait a moment and try again.';
  if (status >= 500) return `TMDB is having problems (${status}). Try again later.`;
  return `TMDB error ${status}${apiMessage ? `: ${apiMessage}` : ''}`;
}

export async function fetchMovies({ type, page, language, region, token, fetchImpl = fetch }) {
  if (!token) {
    throw new UserError('TMDB access token is missing. Put TMDB_ACCESS_TOKEN in .env (see README).');
  }

  let response;
  try {
    response = await fetchImpl(buildUrl({ type, page, language, region }), {
      headers: { Authorization: `Bearer ${token}`, accept: 'application/json' },
      signal: AbortSignal.timeout(TIMEOUT_MS),
    });
  } catch (err) {
    const reason = err.name === 'TimeoutError' ? 'request timed out' : (err.cause?.code ?? err.message);
    throw new UserError(`Cannot reach TMDB: ${reason}. Check your internet connection.`);
  }

  if (!response.ok) {
    let apiMessage;
    try {
      apiMessage = (await response.json()).status_message;
    } catch {
      // тіло помилки може бути не JSON — тоді вистачить коду статусу
    }
    throw new UserError(httpErrorMessage(response.status, apiMessage));
  }

  try {
    return await response.json();
  } catch {
    throw new UserError('TMDB returned an invalid response.');
  }
}

Усе в одному місці: валідація, URL, запит, помилки. Працює, але щоб додати другий API, довелось би копіювати блок із try/catch і розбором статусів.

8. MovieFormatter: показ окремо від даних

src/MovieFormatter.jsпрезентація
// Показ: перетворює MoviePage на текст для терміналу. Окремий клас, бо «як показати» — це
// незалежне рішення: CliApp отримує форматер ззовні, і його можна замінити (наприклад, на JSON).
export class MovieFormatter {
  static ATTRIBUTION = 'This product uses the TMDB API but is not endorsed or certified by TMDB.';

  formatRating(movie) {
    if (!movie.hasRatings) return 'no ratings yet';
    const votes = movie.voteCount === 1 ? '1 vote' : `${movie.voteCount} votes`;
    return `${movie.voteAverage.toFixed(1)}/10 (${votes})`;
  }

  formatMovie(movie, number) {
    const head = `${number}. ${movie.title} (${movie.year}) - ${this.formatRating(movie)}`;
    const overview = movie.shortOverview;
    return overview ? `${head}\n   ${overview}` : head;
  }

  format(moviePage, listType) {
    const header = `${listType.title} movies - page ${moviePage.page} of ${moviePage.totalPages}`;
    if (moviePage.isEmpty) return `${header}\n\nNo movies found.`;
    const entries = [...moviePage.numbered()].map(({ number, movie }) => this.formatMovie(movie, number));
    return `${header}\n\n${entries.join('\n\n')}`;
  }
}
  • Клас без власного стану: лише методи. Навіщо тоді клас? Щоб CliApp отримував його ззовні. Нащадок JsonMovieFormatter з тим самим методом format замінив би його без змін у CliApp (див. вправи).
  • Статичне поле ATTRIBUTION — константа класу, до неї звертаються як до MovieFormatter.ATTRIBUTION, без створення об'єкта.
  • Дрібні методи (formatRating, formatMovie) можна перевизначити окремо, не переписуючи format.

import { parseArgs } from 'node:util';
import { ListType } from './ListType.js';
import { PageNumber } from './PageNumber.js';
import { MovieFormatter } from './MovieFormatter.js';
import { UsageError, UserError } from './errors.js';

// Застосунок командного рядка: розбирає аргументи, просить клієнта список і друкує його.
// Усі залежності приходять через конструктор (ін'єкція залежностей), а не створюються тут:
//   • createClient(token) — фабрика клієнта, у тесті підставляємо фейковий;
//   • formatter — як показувати; • stdout/stderr — куди друкувати.
export class CliApp {
  static OPTIONS = {
    type: { type: 'string', short: 't' },
    page: { type: 'string', short: 'p' },
    language: { type: 'string', short: 'l' },
    region: { type: 'string', short: 'r' },
    help: { type: 'boolean', short: 'h' },
  };

  static HELP = `Usage: tmdb-app --type <${ListType.keys().join('|')}> [options]

Types:
  playing   movies that are in theatres now
  popular   popular movies
  top       top rated movies
  upcoming  upcoming movies

Options:
  --type <name>       which list to show (required)
  --page <n>          page number, 1-500 (default 1)
  --language <code>   language of titles and overviews, e.g. uk-UA (default en-US)
  --region <code>     country code for release dates, e.g. UA
  --help              show this help

The token is read from TMDB_ACCESS_TOKEN (environment variable or .env file).
`;

  #config;
  #createClient;
  #formatter;
  #stdout;
  #stderr;

  constructor({ config, createClient, formatter = new MovieFormatter(), stdout = console, stderr = console }) {
    this.#config = config;
    this.#createClient = createClient;
    this.#formatter = formatter;
    this.#stdout = stdout;
    this.#stderr = stderr;
  }

  // Повертає код виходу: 0 — успіх, 1 — помилка. Помилки не вилітають назовні, а друкуються тут.
  async run(argv) {
    try {
      await this.#execute(argv);
      return 0;
    } catch (err) {
      this.#stderr.error(CliApp.isKnownError(err) ? `Error: ${err.message}` : err);
      return 1;
    }
  }

  // «Відома» помилка = користувач міг її виправити (наша UserError або помилка розбору аргументів Node)
  static isKnownError(err) {
    return err instanceof UserError
      || err?.code === 'ERR_PARSE_ARGS_UNKNOWN_OPTION'
      || err?.code === 'ERR_PARSE_ARGS_INVALID_OPTION_VALUE';
  }

  async #execute(argv) {
    const { values } = parseArgs({ args: argv, options: CliApp.OPTIONS });
    if (values.help) return this.#stdout.log(CliApp.HELP);
    if (values.type === undefined) throw new UsageError(`Missing --type.\n\n${CliApp.HELP}`);

    const listType = ListType.parse(values.type);
    const page = PageNumber.parse(values.page);

    const client = this.#createClient(this.#config.token);
    const moviePage = await client.list(listType, { page, language: values.language, region: values.region });

    this.#stdout.log(this.#formatter.format(moviePage, listType));
    this.#stdout.log(`\n${MovieFormatter.ATTRIBUTION}`);
  }
}

import { existsSync, readFileSync } from 'node:fs';

// Вміст .env-файлу: рядки KEY=VALUE, коментарі з #, значення можна брати в лапки.
// Значення ховаються в приватне поле (#values): ззовні їх читають лише через get().
export class EnvFile {
  #values;

  constructor(values = {}) {
    this.#values = { ...values };
  }

  // Розбір тексту (без файлової системи: легко тестувати)
  static parse(text) {
    const values = {};
    for (const line of text.split(/\r?\n/)) {
      const match = /^\s*([A-Za-z_]\w*)\s*=\s*(.*?)\s*$/.exec(line);
      if (!match) continue; // порожній рядок, коментар або сміття
      values[match[1]] = match[2].replace(/^(["'])(.*)\1$/, '$2');
    }
    return new EnvFile(values);
  }

  // Файлу немає — це не помилка: повертаємо порожній EnvFile
  static load(file) {
    return existsSync(file) ? EnvFile.parse(readFileSync(file, 'utf8')) : new EnvFile();
  }

  get(key) {
    return this.#values[key];
  }

  toObject() {
    return { ...this.#values };
  }
}

  • Config.load({ env, envFile }) отримує process.env параметром, тож тест передає свій об'єкт. Правило «змінна середовища важливіша за .env» записано в одному рядку й покрите тестом.

const sink = () => {

  1. JsonMovieFormatter. Зроби клас JsonMovieFormatter extends MovieFormatter з методом format, що повертає JSON.stringify. Додай прапорець --json у CliApp. Скільки файлів зміниться? (Підказка: у CliApp формат уже береться з поля.)

Перевір себе: чим PageNumber кращий за просте число?

Просте число може бути будь-яким, тож кожен, хто його отримує, мусить перевіряти сам або довіряти. PageNumber перевіряється один раз, у конструкторі, і потім у системі існують лише правильні значення. Це називається «зробити неправильні стани неможливими».

Перевір себе: чому ApiClient не створює fetch сам, а отримує його в конструкторі?

Тоді у тесті можна підставити підроблений fetch і перевірити всі гілки помилок без мережі. Передача залежності ззовні (ін'єкція) робить клас перевірюваним і незалежним від того, звідки береться HTTP.
